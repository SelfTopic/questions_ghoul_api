# Что отдаёт Fandom-вики

## Язык: есть русская версия, скрапить её

У вики есть полноценная русскоязычная версия — не просто интервики-ссылка, а
отдельный контент: `https://tokyoghoul.fandom.com/ru/wiki/...`, API —
`https://tokyoghoul.fandom.com/ru/api.php` (тот же механизм доступа, тоже не
за Cloudflare-проверкой). Статистика (`meta=siteinfo&siprop=statistics`):
1360 статей, 5835 изображений — заметно меньше английской версии, но всё
равно сильно больше текущих 500 вопросов.

Структура шаблона и секций **идентична английской** — имена полей инфобокса
те же (`rc type`, `rating`, `rc level`...), меняются только значения
(«Ринкаку», «SS» вместо «Rinkaku», «SS»), секция цитат называется «Цитаты» с
теми же подразделами по произведениям, категории — `Категория:...` сразу на
русском (`Категория:Ранг SS`, `Категория:Члены «Антейку»`). Значит:
**перевод не нужен**, парсер инфобокса/цитат пишется один раз и работает для
обоих языков без изменений (меняется только базовый URL с `/api.php` на
`/ru/api.php`). Скрапер должен целиться в русскую версию — у текущих данных
(`data.json`) язык русский, переводить с английского было бы лишней работой
и источником ошибок.

Возможный риск: сообщество-перевод может быть менее полным/актуальным, чем
английский оригинал (отстаёт по новым главам, мельче по охвату) — но для
старта 1360 статей более чем достаточно, пересмотреть можно по факту, если
не хватит материала на конкретную тему.

Разведка структуры `tokyoghoul.fandom.com` для дизайна скрапера. Проверено
прямыми запросами к MediaWiki API, не догадками.

## Доступ: через API, не через HTML-страницы

Рендеренные страницы (`/wiki/...`) закрыты Cloudflare-проверкой — обычный
HTTP-клиент получает `403` с JS-challenge, нужен браузер. Но
**`https://tokyoghoul.fandom.com/api.php`** (стандартный MediaWiki Action API)
открыт свободно и отдаёт чистый JSON без всякой защиты. Значит скрапер должен
ходить через API (`action=parse`, `action=query`), а не рендерить страницы —
заодно не нужен headless-браузер (Playwright и т.п.), простого HTTP хватает.

Два режима `action=parse`:
- `prop=wikitext` — исходный wikitext с невыполненными шаблонами
  (`{{ChapterRef|1}}`, `{{birth date|...}}`, `{{#tag:tabber|...}}` для
  картинок и т.п.) — простые вещи (инфобокс-поля, цитаты-булеты) парсятся
  регулярками, но ссылки/даты/картинки с вложенными шаблонами — нет, если не
  писать свой MediaWiki-препроцессор.
- `prop=text` — уже отрендеренный HTML, шаблоны раскрыты самой вики. Для
  текстовых секций (описание, отношения) проще разбирать это, а не
  реализовывать разворачивание шаблонов самому.

Практический вывод: инфобокс и цитаты (простой формат, см. ниже) — брать из
`wikitext` регулярками; всё остальное текстовое — из `text` (HTML) через cheerio.

## Инфобокс: один шаблон на людей и гулей

`{{Character}}` (см. `Template:Character/doc`) — единый для всех, не
отдельные шаблоны на гуля/человека/следователя. Полный список полей:

```
image, name, kanji, romaji, alias, species, status, age, gender, sex,
birthday, birthdate, death date, height, weight, foot length, blood type,
affiliations, occupation, relatives, ward,
rc type, rc level, unique ghoul states, rating,       # гуль-специфичные
quinque, investigator entry class, ccg division, rank, # CCG-специфичные
honors, manga debut, anime debut, novel debut, game debut,
jp voice, en voice, stage play, film actor
```

Подтверждено на реальных страницах:
- `rc type` = тип кагуне (Канеки → `Rinkaku`). Это и есть `answer_group:
  kagune_type` из текущих данных.
- `rating` = ранг опасности **гуля** (Норо → `SS~`). Это `answer_group: rank`
  для гулей — но не путать со следующим полем.
- `rank`/`ccg division` = ранг **следователя CCG** — у Канеки после перехода
  на сторону CCG заполнено и то, и другое отдельно от `rating`. Разные поля,
  разный смысл, один и тот же текстовый лейбл «ранг» в бытовом языке.

## Темы: категории уже готовы

`[[Category:...]]` в wikitext каждой страницы — ровно то, что мы решили
использовать как теги тем (топики обнаруживаются при парсинге, не хардкодятся
— см. `topics.md`). Примеры с реальной страницы Канеки: `Characters`,
`Aogiri Members`, `Ghoul Investigators`, `Kakuja`, `Anteiku Members`,
`TG Characters`, `TG:re Characters`, `One-eyed ghoul`, `Alive`. Плюс
мета-категории вроде `Characters by organization`/`by species`/`by status` —
удобные группы тем верхнего уровня.

## Цитаты: готовый формат с атрибуцией и источником

На каждой странице персонажа — секция `== Quotes ==`, с подсекциями по
произведению (`=== Tokyo Ghoul ===`, `=== Tokyo Ghoul: Days ===`,
`=== Tokyo Ghoul:re ===`). Формат одной цитаты:

```
* Кому (контекст): "текст цитаты"{{ChapterRef|47}}
* Кому: "текст цитаты"{{EpisodeRef|1}}
```

Атрибуция автора — сама страница, на которой лежит цитата (не нужно отдельно
парсить "кто сказал"). Источник уже помечен: `ChapterRef` = манга-глава,
`EpisodeRef` = эпизод аниме — то есть для каждой цитаты сразу известно,
аниме это или манга, без дополнительного анализа.

## Аниме/манга-развилка — открытый вопрос №14 закрыт

Фандом хранит это не одним способом, а несколькими одновременно:
1. Категория **`Anime-Only Characters`** — персонажи, которых нет в манге.
2. Отдельные топ-секции на странице персонажа: **«Manga Depiction»** и
   **«Anime Depiction»**, каждая со своими подсекциями по сериям — то есть
   готовый текст про то, чем сюжетная линия в аниме отличается от манги.
3. Инлайн-пометки прямо в полях инфобокса, например
   `affiliations = ...[[Aogiri Tree]] - Executive (Anime only; Defected)...`
4. Отдельные поля `manga debut` / `anime debut` / `novel debut` / `game debut`.
5. Цитаты помечены `ChapterRef` (манга) или `EpisodeRef` (аниме) — см. выше.

Значит оба варианта из п.14 (фильтр по источнику и отдельные вопросы на
знание различий) реализуемы на реальных данных, а не только в теории.

## Инвентарь контента и MVP-скоуп

Разбор категорий русской вики (без картиночного/служебного шума, ~620 →
256 содержательных категорий) по видам страниц:

| Вид страниц | Страниц |
|---|---|
| Персонажи | 291 (гули — 116, следователи/CCG — 86+83, из новелл — 18) |
| Куинке (оружие) | 54 |
| Локации | 54 (районы — 24 из них) |
| Термины (глоссарий) | 42 |
| Организации | 25 |
| Сюжетные арки | 22 + отдельные страницы арок (~15–40 каждая) |

Готовые измерения-теги (уже категории на вики, не придумывать самим):
по типу кагуне (Ринкаку/Бикаку/Коукаку/Укаку/Какуджа — то же самое есть и у
куинке, Rc-тип и ранг), по рангу опасности (S/SS/SSS/A), по расе
(Гули/Люди/Полулюди/Одноглазые гули), по организации, по статусу
(Погибшие/Пропавшие без вести).

**Решено**: MVP скрапера — **только персонажи** (291 страница). Это
расширяет то, что уже есть (все 500 текущих вопросов — про персонажей),
и уже разобранные выше инфобокс/цитаты/категории дают: больше вопросов
текущего формата, тему по типу кагуне/рангу, вопросы на авторство цитат,
аниме/манга-развилку. Локации/организации/куинке/термины/арки — явно не
в первом проходе, добавляются каждый своим парсером позже (скрапер должен
трактовать «вид страницы» как отдельный плагин/парсер, а не монолит, чтобы
это расширение было дёшевым).

## Вторая волна: термины — сделано

41 страница из «Категория:Термины» (не 42 — одну с момента первой разведки
переименовали/удалили). В отличие от персонажей, у терминов **нет
инфобокса** — чистая проза с заголовками `==Раздел==`, хвост — секции
«Примечания»/«Навигация по сайту» (обрезаются), таблицы (`{| ... |}`)
убираются целиком независимо от названия секции (чистый текст не из них не
собрать). Скрапер — `scripts/scraper/terms/`, переиспользует общий
`fetchContent` из скрапера персонажей.

Генерация вопросов — **без субагентов**: всего 41 термин, уложился в
прямое ручное авторство (в отличие от 281 персонажа, где обязательно
нужны были параллельные субагенты). 61 вопрос, формат как в текущем
`data.json` (категория `term`): "Как называется X, который Y?" →
название термина, или наоборот. Локации/организации/куинке — ещё не
сделаны, та же механика скрапинга подойдёт, но инфобокс у них может быть
другим (не проверено).

## Открыто для следующего шага

Это разведка по одной странице (`Ken Kaneki`) и выборочным полям — не аудит
всей вики. Перед тем как писать сам скрапер, стоит посмотреть ещё: страницу
не-персонажа (локация, организация, квинке — у них, вероятно, другие
инфобокс-шаблоны), и как выглядит `rc type`/`rating` у персонажей без явного
значения (гуль неизвестного ранга, человек без кагуне вообще).
